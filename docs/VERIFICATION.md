# 这个插件是怎么被验的

> 一份诚实的验证记录：哪些结论有运行时证据、哪些只有单测、哪几处缺陷是真实踩出来的。
> 日期：2026-11-15 · 版本 0.3.1

## 1. 证据分层（越靠下越强）

| 层 | 能证明 | 不能证明 |
| --- | --- | --- |
| 单元测试（58 条） | 纯逻辑：归一化、编号、回填句、收口语义 | 模块能否装配 |
| 假 ctx 夹具 | 宿主半的路由、工具、事件订阅在**假环境**下正确 | 真实宿主是否这样广播 |
| **真实运行时**（真 Harness + 真文件） | 插件能装、能注册、事件真的来 | 别的宿主版本 |
| **真实客户端**（真 Chromium） | 协议与渲染可用 | — |

结论只写在对应层能证明的范围内。下面标「运行时」的，都是在这台机器上真的跑出来的。

## 2. 十轮里真实踩到的缺陷（都已修，且留了守卫）

| # | 症状 | 根因 | 现在的守卫 |
| --- | --- | --- | --- |
| 1 | 点选项报 `cannot resolve a workspace directory` | decide 的 URL 漏了 `sessionId`，宿主反查不到工作目录 | 两个端点共用 `endpointUrl`，回退即红 |
| 2 | 回填的文字被改写、出现「校对中」 | 会话共享的 `inputActions.insertText` 被别的插件猴补丁成「转写 → LLM 校对 → 延迟写回」 | 填充改走 `setDraft`；断言被补丁的 `insertText` **从未被调用** |
| 3 | 点了选项，条目从待拍消失，但消息根本没发 | 点选直接写 `decided` | 引入 `filled`（已回填·待发送），未确认不出清单 |
| 4 | 未知 id 的收口也回 200 | 构造 Response 时吞掉了 status | 回真实状态码；回归测试盯 200/400 |
| 5 | 人手加的自定义字段写回后丢失 | 用归一化后的副本回写 | 从 `raw` 写回；测试断言未知字段存活 |
| 6 | 轮询每秒重建 DOM，点按钮点空 | 每秒重渲染，点击落在已丢弃的节点上 | `setView` 比对视图签名，没变就不重建 |
| 7 | 「要不要」型没有按钮，只能自己打字 | 空 `options` 被当成「没有选项」 | 合成 `是/否` 并标 `synthetic`（不冤枉作者「未给代价」） |
| 8 | 工具描述写着工作区级路径、且没有 `add`，但行为早改了 | 行为改了、文档没改，测试全绿 | **断言描述里必须出现 `action=add` / 会话级路径 / 「要人拍板时」** |
| 9 | 服务还没就绪时注册静默失败 | `apply` 时直接 `ctx.get()` | 改为 `ctx.inject([name], …)` 等服务就绪，伪 ctx 退回 `get` |

第 8 条值得单独说：它不是代码 bug，跑什么都对。它坏的是「拿到插件的人能不能用起来」——
模型只看工具描述，描述不提 `add`，就没有人会往里写条目。**只有断言能自动发现它。**

## 3. 守卫「会红」是验过的，不是假设的

| 守卫 | 怎么证明它会红 |
| --- | --- |
| 端点必须带 `sessionId` | 把 `endpointUrl` 回退成不带参数的旧写法 ⇒ 测试红 |
| 填充不许走 `insertText` | 让代码改回 `insertText` ⇒ 断言「未被调用」红 |
| 未确认不出清单 | 让点选直接写 `decided` ⇒ `openItems` 断言红 |
| 描述不许漂移 | 删掉描述里的 `action=add` ⇒ 描述守卫红 |

## 4. 运行时证据（真机，非夹具）

| 项 | 观测 |
| --- | --- |
| 数据文件不存在 | 看板显示 `待拍 0` 与空态文案，不报错、不猜 |
| 外部写入一条 pending | 卡片 **1248 ms** 后出现，角标变 `待拍 1`（轮询 2000 ms） |
| 模型写 `:::decisions` 块 | 文件里自动出现条目，编号自增，选项与原文一致 |
| 人回一句 `Q-2 选 B` | 同秒落 `decided`，`by: user-message` |
| 从零 clone 后跑测试 | `git clone` → 不装依赖 → `node --test` **58/58** |

### 端到端那条链（六段，全在运行时）

1. 插件注入一段系统提示（告诉模型 `:::decisions` 格式）——**我的上下文里确实出现了这段原文**；
2. 模型按协议写块，**没有调用任何工具**；
3. 插件解析块并落盘，编号自动排到 `Q-2`（`Q-1` 已定，未撞号）；
4. 人从看板看到条目并回答；
5. 插件订阅 `user/message`，同秒标记 `decided`。

中间没有人工步骤、没有工具调用、没有改任何项目配置。

## 5. 已知边界（没验到的，明写）

- **只在当前 Harness 版本上验过**。`systemPrompt.section()` 与 `session/event` 的形态若变，注入或捕获会失效；
- **浏览器半只测了 Chromium**；`●` 徽标与抽屉的样式没做跨浏览器回归；
- **`dsh.client.inject` 含 `dsh-desktop-workbenches`** —— 这是 Desktop 安装器的要求；纯 web 端能否加载未验；
- **不做跨会话总览**，这是有意为之：每个会话只看自己那份文件；
- 面板最多渲染最近 5 条已定条目，更早的只在文件里。
